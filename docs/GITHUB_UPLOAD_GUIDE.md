# 怎么把你写的东西上传到 GitHub（写给初学者）

2026-11-14，CC 起草。**不需要装任何软件，用浏览器就能完成。** 全程大约 10 分钟，第一次会慢一点。

## 0. 先说清楚：上传什么，不上传什么

**只上传这三类文件，都是 Markdown（`.md`）文本文件：**

| 要上传的 | 放进哪个文件夹 | 文件名例子 |
|---|---|---|
| 课题卡 | `topics/` | `T001_ctnnb1_immune.md` |
| 分析说明书 | `frameworks/` | `A2_multi_gene_batch.md` |
| 你的疑问清单 | `frameworks/` | `QUESTIONS.md` |

**不要上传：**
- 数据文件（表达矩阵、表格等）：太大，也不是你的任务；
- 论文的 PDF：有版权，只记 PMID 或 DOI 就行；
- 代码；
- 任何**密码、令牌、身份证号、手机号、邮箱**；
- 仓库里**别的文件夹**的改动。

**文件名规则**：只用英文字母、数字、下划线，不要空格和中文。说明书用"清单编号 + 英文简称"。

## 1. 一次性准备（只做一次）

1. **注册 GitHub 账号**（github.com，免费）。**自己注册，不要把密码给任何人，包括我们。**
2. 把你的 **GitHub 用户名**告诉项目负责人。他会邀请你加入仓库。
3. 你的邮箱会收到一封邀请邮件。**点邮件里的 "View invitation"，再点 "Accept invitation"。**
4. 打开仓库链接，能看到文件列表，就说明成功了。

## 2. 每次上传的步骤（网页方法）

**第 1 步：进入要放文件的文件夹**
在仓库首页点 `frameworks`（或 `topics`）。

**第 2 步：上传文件**
点右上角 **"Add file"**，选 **"Upload files"**。把你的 `.md` 文件**拖进页面中间**，或点 "choose your files" 选择。等文件名出现在列表里。

**第 3 步：写提交说明，选新分支**
滚动到页面下面的 "Commit changes" 区域：
- 第一个框写一句话说明，格式见第 4 节。
- **一定要选下面的 "Create a new branch for this commit and start a pull request"**，不要选 "Commit directly to the main branch"。
- 分支名可以不改，用默认的。
- 点绿色按钮 **"Propose changes"**。

**第 4 步：创建拉取请求（Pull Request）**
下一页点绿色按钮 **"Create pull request"**。
- **标题**：`[说明书] A2 多基因批量`（或 `[课题卡] T001 …`）。
- **描述**写三件事：做了什么；有哪些"待定"；想问什么。
再点一次 **"Create pull request"**。

**第 5 步：等待**
项目负责人和 AI 会在这个页面里评论。你会收到邮件提醒。评论里会说：可以合并，或者需要改哪里。

**第 6 步：如果要改**
1. 在这个拉取请求页面，找到类似 `你的用户名:分支名` 的链接，点进去，就回到你的分支；
2. 进入对应文件夹，再点 **"Add file" → "Upload files"**，拖入**同名**的修改后文件（会覆盖旧的）；
3. 这次在 "Commit changes" 区域选 **"Commit directly to the 分支名 branch"**（就是你自己的分支）；
4. 点 "Commit changes"。拉取请求会**自动更新**，不用重新创建。

**第 7 步：合并**
项目负责人确认没问题后，会点 **"Merge pull request"**，也就是"接受"。你会看到状态变成紫色的 **Merged**。到这里这一份就交付完成了。

## 3. 如果你更习惯用软件：GitHub Desktop

也可以。装好 GitHub Desktop，登录，克隆仓库到本地，**新建一个分支**，把文件复制进 `topics/` 或 `frameworks/`，写提交说明，点 Commit，再点 Push，最后点 "Create Pull Request"。其余和上面一样。**不会用就用上面的网页方法。**

## 4. 提交说明和标题的写法

| 类型 | 提交说明 | 拉取请求标题 |
|---|---|---|
| 课题卡 | `topic: T001 CTNNB1 immune exclusion` | `[课题卡] T001 CTNNB1 免疫排斥` |
| 说明书 | `spec: A2 multi-gene batch` | `[说明书] A2 多基因批量` |
| 修改 | `fix: A2 add negative control` | `[修改] A2 补阴性对照` |
| 疑问 | `questions: update` | `[疑问] 更新问题清单` |

**一个拉取请求只放一个分析的内容**，不要一次放十几个，否则看的人没法评论。

## 5. 常见问题

| 问题 | 怎么办 |
|---|---|
| 看不到 "Upload files" 按钮 | 多半是没有接受邀请，或没有写权限。看邮箱，或告诉项目负责人 |
| 上传错了文件 | 不要紧。关闭这个拉取请求（页面下面 "Close pull request"），重新做一次。历史不会被删 |
| 文件名带中文，显示乱码 | 改成英文名重新上传 |
| 一次传多个文件 | 可以，但同一个拉取请求里只放**一个分析**相关的文件 |
| 被要求"解决冲突" | 不要自己处理，告诉项目负责人 |
| 不确定该不该上传某个文件 | **不要传**，先问 |

## 6. 隐私与安全

- 如果仓库是**公开**的，任何人都能看到你上传的所有内容。不要上传不想公开的东西。
- **不要把 GitHub 的密码、令牌给任何人。** 项目负责人和 AI 都不需要它们。
- 你的 GitHub 用户名会出现在每一次提交上，这是正常的，说明是你写的。

## 7. 收到之后，我们会做什么

1. 看拉取请求里的文件，在页面里评论。
2. 说明书：AI 会判断数据够不够、方法对不对、跟文献有没有矛盾，把意见写在评论里。
3. 没问题就合并（接受）。合并之后，AI 会按说明书去做。
